// what it checks

Eleven fields. In priority order.

01–03

Identify the thing

Symptom, OS and version, runtime or dependency version.

04–07

Make it reproducible

Exact steps, expected value, actual value, the real error text.

08–09

Narrow the search

Frequency, and what does not trigger it — the answer almost nobody asks for.

10–11

Be honest

Minimal reproduction, and what the reporter did not test.

// what it doesn't do

We don't reproduce your bug.

ReproKit never claims to reproduce anything. It doesn't run your code, doesn't execute a reporter's steps, and doesn't guess a root cause. It produces the evidence that makes reproduction possible — and tells you plainly when a report still isn't rerunnable.

If the evidence isn't there, the verdict says so. You get the exact list of missing fields instead of a green tick that means nothing.

  • No login needed to try it on a public issue
  • Secrets are redacted server-side before storage, with a visible count
  • Nothing is posted to GitHub automatically — you copy the Markdown and post it yourself
  • No repo access, no CI setup, no maintainer-side install
  • No accounts, no analytics identifiers, reports expire automatically
